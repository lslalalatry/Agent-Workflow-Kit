# Phase 3 手册：中英双语适配版 ASD-STE100 受控技术写作规范

航空工业标准 **ASD-STE100（Simplified Technical English）** 的核心思想是消灭自然语言的两大误读根源：**一个词有多种意思**、**一句话有多种断句结构**。
将这一标准适配到**中文+代码/公式混合的「追踪文档」**中，能彻底根治 AI 把状态文档写成晦涩万字长文、上下游理解错位的问题。

---

## 一、双模式边界：规则锁死 vs 真实不确定性保留

动笔前先区分句子性质（与全局 `asd-ste100` 技能完全对齐）：
1. **指令与契约句（Strict 严格模式 — 用于 `SPEC / FORMULA / TODO / AGENTS`）**
   - 规定系统必须怎么做、严禁怎么做。**全面禁用模糊软词**，只用「必须」、「禁止」、「仅当…时允许」。
2. **观测与状态句（证据保真模式 — 用于 `STATUS / BACKLOG` 风险说明）**
   - 当某件事确实尚未实测或原因待查时，**必须保留真实的证据等级标签**（如 `【推测】可能由缓存未刷新引起，待实测确认`），**绝对禁止为了句子简短把“可能/待查”硬改写成“已经确定”**！

## 二、中英双语 ASD-STE 八大结构改写对照表

| 法则 | ❌ 违规病句示范（易引发 AI 误读与漂移） | ✅ 合规改写示范（零歧义、可直接转代码） |
| :--- | :--- | :--- |
| **1. 一词一义**<br>（禁同义词轮换） | “导入**配置表**后刷新**设置项**，若**参数选项**为空则用默认**偏好**。” | “导入 `config` 表后重新加载 `config`；若必填字段为 `NULL`，则报错阻断。” |
| **2. 强情态词**<br>（禁模糊软词） | “金额汇总时**原则上建议尽量**保留两位小数，**视情况适当**放宽误差。” | “汇总函数**必须**使用整数分运算并保留 2 位小数；校验容差**必须** `<= 0.01`。” |
| **3. 一句一指令**<br>（禁长句串写与分号） | “解析上传文件并去重合并后触发全表重算；同时刷新顶部筛选项并校验差额是否超限，若超限则置灰导出按钮。” | 拆为有序短句：<br>1. 解析上传文件并按唯一键幂等合并。<br>2. 执行全表重算并刷新筛选项。<br>3. 若校验差额 `> 0.01`，则禁用导出按钮。 |
| **4. 主动语态**<br>（明示执行主体） | “未匹配的记录会被自动隔离，并在稍后由界面提示核查。” | “`matcher` 模块将未匹配记录标记为 `unmatched`；明细视图在页顶显示待核查条数。” |
| **5. 条件前置**<br>（先条件后动作） | “直接覆盖旧记录，除非新记录指纹完全一致（此时跳过）或已被人工锁定。” | “若记录已被人工锁定或指纹完全一致，则跳过写入；否则用新记录覆盖旧记录。” |
| **6. 零悬空指代与水分**<br>（禁空洞形容词） | “重构**它**以保持**上述逻辑原样**，提供**更稳健丝滑的高性能**体验。” | “重构 `renderTable()` 为虚拟滚动：保持输出字段不变，5 万行首屏渲染耗时 `< 80 ms`。” |
| **7. 名词簇解耦**<br>（禁超长定语堆叠） | “执行跨渠道月度父体销量池动态权重重分配回退校验逻辑。” | “执行 `validatePoolFallback()`：校验父体销量按权重分配后的总和是否守恒。” |
| **8. 表格替代散文**<br>（3 分支以上转表） | 在一段 300 字文字里连续描述状态 A 怎么显示、状态 B 怎么算、状态 C 怎么报错…… | 直接改为 `状态枚举 \| 触发条件 \| 计算行为 \| 界面展示` 四列 Markdown 表格。 |

## 三、落盘前 30 秒快速自检清单

更新 `docs/tracking/` 任何文档前，快速扫视：
- [ ] **句长检查**：有没有超过 2 行（>45 字）的复合长句或分号 `;`？有则拆开。
- [ ] **词表检查**：新出现的业务名词或枚举值，是否已在 `SPEC.md` 第 2 节登记？
- [ ] **主体检查**：每条规则是否都能一眼看出“哪个模块/脚本做这件事”？
- [ ] **边界检查**：新定义的字段或公式，是否写清了 `0 / NULL / 负数 / 重复 / 缺失`？
- [ ] **体量检查**：`STATUS.md` 是否仍在 **100 行以内**？（多出的历史过程立刻剪贴到 `BACKLOG.md` 第三节）。
