# Phase 4 & 5 手册：单主线隔离、零冗余存储与长任务防失忆接力

本手册规定编码与验证执行期的硬性卫生纪律，防止长周期任务出现**分支乱麻、数据库与大文件克隆膨胀、单轮大改流中断失忆、以及未完全验证提前勾选完成**。

---

## 一、Git 单主线实验收口协议（Single-Trunk Protocol）

1. **常态唯一主干**：仓库日常只允许存在唯一主分支 `main`（存量老项目若为 `master` 同理）。
2. **何时拉出临时实验分支**：仅当进行高风险探索（如对比两种底层算法、大范围渲染/架构替换）需要随时无损丢弃时，才创建 `exp/<short-topic>`。
3. **当轮闭环收口铁律（严禁带实验分支跨任务）**：
   - **实验成功**：
     ```bash
     git checkout main
     git merge --no-ff exp/<short-topic> -m "merge: integrate exp/<short-topic>"
     git branch -d exp/<short-topic>
     ```
   - **实验放弃**：
     ```bash
     git checkout main
     git branch -D exp/<short-topic>
     ```
4. **多 Worktree 禁令与 Swarm 特例**：除非用户明确启动多代理并行（如 `/swarm` 会话），否则**默认禁止创建 `git worktree`**（尤其在含大型依赖或本地数据的项目中，极易产生多套重复缓存与残留目录）。进入 `/swarm` 模式时，仅允许按 [08-swarm-orchestration.md](./08-swarm-orchestration.md) 为 Author 分配 `share` 工作区与 `swarm/<worker>` 分片分支，合回主干后必须立即清理销毁。

## 二、数据库与大体积资产「四级零克隆隔离阶梯」

严禁把“复制一份全量数据库”或“复制整个项目文件夹”当作常规测试手段：

| 任务级别 | 适用场景 | 强制隔离方式 | 严禁行为 |
| :--- | :--- | :--- | :--- |
| **L0 · 零写级** | UI 布局、样式、文案、纯展示交互调整 | 直接连接唯一受管本地实例只读预览，零数据写入 | 禁止新建任何数据库、快照或新开测试端口 |
| **L1 · 轻量逻辑级** | 查询改写、分类/清洗规则、公式计算、导入解析测试 | ① 以 `READ_ONLY` 模式打开原库 + 挂载内存临时表/视图；或<br>② 构建覆盖正常例与全部边界反例的**微型夹具库（Fixture，KB~MB 级）**跑自动化测试 | 禁止拷贝 GB 级生产/历史全量库跑单测 |
| **L2 · 全量候选级** | 必须对全量数据做落盘迁移或重算验收 | ① 开工前先向用户报告预计峰值体积与当前磁盘剩余空间；<br>② 仅写入 `AGENTS.md` 白名单登记的**唯一候选槽位**（如 `data/candidates/active_candidate.*`）；<br>③ 验收替换或放弃后，立即按规清理或回收临时候选，严禁按日期无限叠加 `v1/v2/1118` 副本 | 禁止在 `.gitignore` 掩护下在硬盘堆积多份未登记全量库 |
| **L3 · 服务实例级** | 本地前后端联调、预览服务器运行 | 复用 `AGENTS.md` 登记的唯一标准端口；启动前先检查该端口是否已有健康实例，收尾时清理临时子进程 | 禁止同时遗留 `:8000 / :8001 / :8145` 等多个连不同代码的僵尸后台 |

## 三、长任务防流中断与跨窗口「零失忆」接力机制

1. **2–5 分钟原子微任务切片（防单轮流中断）**
   - 严禁在单轮响应中一次性连续修改数千行单文件或十几个跨层模块。
   - 按 `TODO.md` 每次只聚焦 **1 个独立可验证的微任务** -> 运行验证命令 -> 刷新追踪文档 -> 到交接节点检查本地存档及远端同步状态，按已有授权处理。
2. **`STATUS.md` 断点接力锚点（防换窗口失忆）**
   - 每次提交前，必须把 `STATUS.md` 第 2 节 **「断点接力锚点」** 更新到最新真实状态：
     - **上一完成微任务**：写明刚通过验证的任务 ID 与结果；
     - **当前工作区状态**：写明主干是否干净、有无处于 `[~]` 待用户终验的候选；
     - **下一步精确指令**：写明下一轮接手时第一件事读哪个文件、跑哪条命令、改哪个函数。
   - 效果：无论中途发生网络流中断、上下文窗口压缩，还是第二天新开聊天窗口，应重读工作区内的决定、状态和本次涉及的规则，核对未提交的最新变动。
3. **任务完结与主动换窗信号**：
   - 当当前子模块（如 `docs/architecture/modules/<name>.md`）已通过验收且按项目 `delivery_mode` 完成本地存档与 `main` 推送后，AI 必须在回复末尾主动提示 **「🟢 本任务已完结，建议立即新开对话框」**，防止旧对话上下文污染下一模块。

## 四、三态验证与防越界勾选门禁

1. **验证结果三态分明**：
   - `pass`：已实际执行且观测结果符合预期；
   - `fail`：执行报错或结果偏离契约；
   - `unverifiable`：当前环境缺少某类输入或权限（如无音频轨道、无远端真实账号、未连生产库）无法验证——**必须如实向用户声明不可验证范围，严禁静默算作 `pass`**。
2. **任务勾选三态门禁**：
   - 只要尚未在用户日常使用的**默认正式入口**（全新无特殊参数会话）完成端到端实测，任务最高只能标 `[~]`（候选待验），**严禁把顶层任务标为 `[x]`**。

升为 `[x]` 前执行[默认入口与公式验收](./05-acceptance.md)，在任务旁保留检查 ID 和证据位置。

多对话编辑、批准与取代决定、复用 GitHub 仓库、交接时 commit 和 push 的判断见[共享决定与 Git 交接](./06-shared-decisions.md)。
