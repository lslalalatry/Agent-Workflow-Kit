# 接口契约与界面多态接入清单（API & UI States）

> 本文档约束前后端通信格式、错误码边界以及页面在异常或边缘数据下的真实呈现，防止出现“空值补零、报错静默、筛选失真”等问题。

---

## 1. 接口统一响应与错误码规范

- **成功响应**：保留明确数据主体与口径元信息（如 `data_version`、`scope`、`is_estimated`）。
- **错误响应**：返回结构化 `{ "code": "<ERROR_CODE>", "message": "<可读原因>", "request_id": "..." }`，禁止吞掉异常返回空列表 `[]` 伪装正常。
- **分页与体积硬上限**：所有列表接口强制分页（默认 `limit <= 100`），单次 HTTP 响应体积受控，严禁把全量明细表一次性塞进前端。

## 2. Web 前端基线与现代平台协同（Web 项目适用）

> 纯 CLI、后端服务或非浏览器项目跳过本节。

- **Browser Baseline（兼容基线）**：`<默认 Baseline Widely Available；若需兼容旧端或内嵌 WebView 填写具体浏览器下限>`
- **现代前端能力协同**：编写 HTML / CSS / 前端交互组件（弹窗、Popover、表单校验、表格、暗黑模式、动画、Core Web Vitals 优化）前，若当前环境已安装 `modern-web-guidance` Skill，先执行「搜索定位 (`search`) -> 按需读取 (`retrieve`)」核对浏览器基线与无障碍规范。优先选用 `<dialog>`、`popover`、原生表单验证、CSS Grid / Subgrid / `:has()` 等原生平台能力，禁止为简单交互引入冗余重型第三方 UI 依赖。

## 3. 前端列表与页面多态接入清单（Checklist）

每个数据页面或列表组件上线前，必须逐项勾选验证以下七种真实状态：

| 状态类型 | 触发条件 | 界面与接口必须呈现的行为 | 严禁出现的错误行为 |
| :--- | :--- | :--- | :--- |
| **1. 加载中 (`loading`)** | 首次请求或筛选条件切换等待中 | 显示骨架屏或局部 Loading 提示，禁止阻塞导航 | 页面白屏或仍保留上一次筛选的错误旧数字 |
| **2. 真实空 (`empty`)** | 筛选组合下确实无匹配记录（`total = 0`） | 明确显示“当前筛选无匹配结果”与重置筛选按钮 | 崩溃报错或自动悄悄放宽用户的筛选条件 |
| **3. 真实零 (`zero`)** | 有记录且统计数值本身为 `0` | 如实显示 `0`（或 `0.00`） | 将 `0` 误判为空值显示成 `—` 或隐藏行 |
| **4. 缺失 / 不可验证 (`null / unverifiable`)** | 源数据缺字段、无权限或样本未覆盖 | 显示 `—` / `未提供` / `不可验证` 及原因提示 | **把 `NULL` 静默显示为 `0`** 或把未采当成零 |
| **5. 部分失败 / 降级 (`partial_error`)** | 主 KPI 成功但明细/附图接口超时或 `403` | 正常展示已成功部分，在对应区域提示局部加载失败与重试入口 | 因局部非核心模块挂掉导致整页崩溃 |
| **6. 无权限 (`forbidden / 401`)** | 未登录或角色权限不足 | 引导登录或显示明确的无权限提示 | 暴露堆栈信息或静默停在假加载中 |
| **7. 筛选联动边界** | 多选筛选器与导出（CSV）联动 | 筛选项取自真实事实集；支持「全选 ↔ 全清」；导出范围与页面当前有效筛选严格一致 | 界面显示单选而后台仍按多选查询 |

### 页面级原子断言样例（Expectations，上线前按模块落盘）
- `[ ]` **正常断言**：点击筛选条件并切换分页后，列表数据、`total` 与导出文件行数三者一致。
- `[ ]` **反例断言**：当核心统计字段为 `null` 或子接口返回 `500` 时，页面显示 `—` 与局部重试入口，禁止显示 `0` 或整页白屏。
