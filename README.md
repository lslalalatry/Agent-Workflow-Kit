# Agent-Workflow-Kit · 通用 AI 项目治理与追踪文档工具箱

在 Codex 或 Antigravity 里，用 `project-guardian` 把项目需求、计算口径、待办和验收结果保存在项目文件中。换一个对话，也能从同一份记录继续。

## 快速上手

**已经装好技能？直接在 Codex 或 Antigravity 打开你要做的项目文件夹，从下面选一句发给 AI。** 每个业务项目各自初始化一次。以后继续在原项目里工作。

### 第一次在新电脑安装

准备好 Git 和 Python 3.9 或更高版本。可以把这句话发给 AI，由它完成安装：

> 从 https://github.com/lslalalatry/Agent-Workflow-Kit 下载工具箱。把仓库里的 `skills/project-guardian` 安装到我当前使用的工具中，保留我已有的全局协作规则。安装后告诉我技能的位置，并检查能否运行初始化脚本。

仓库配套的 Codex 技能目录是 `~/.codex/skills/`，Antigravity 技能目录是 `~/.gemini/config/skills/`。如果你想在两端都采用母版的全局规则，见下方「同步母版到两端」。安装完成后，在业务项目里打开新对话。

### 按场景复制一句话

**开新项目**　打开用于新项目的空文件夹，把方括号换成你的想法。

> 调用 `project-guardian` 初始化当前项目。我想做【用一句话描述想法】。先看已有项目里有什么可借鉴，再一次问我一个关键问题，和我确定需求及验收方式。

涉及金额、统计或评分时，补一句 **“开启公式文档，用正常值、边界值和一个易算错的例子核对公式。”** 准备用多个对话协作时，补一句 **“开启决策记录。”**

**接入已有项目**　打开原仓库的根目录。

> 调用 `project-guardian` 接入这个已有项目。先盘点日常使用的入口、数据库和未提交改动，保留业务代码与数据。补齐追踪文档并运行初始化检查，告诉我真实结果和待确认事项。

**日常改功能或修问题**　直接说明要改哪里、做完应该看到什么。例如：

> 默认报表里的均价要按成交件数加权。1 件 10 元、9 件 20 元，结果应为 19 元。把决定同步到相关文档，再从默认报表验收这个例子。

**换对话或第二天接着做**　打开同一项目文件夹。

> 重读当前工作区的决策、TODO、STATUS 和这项任务涉及的产品说明或公式，核对其他对话尚未提交的改动，从上次断点继续。

### 去哪里看结果

| 你想知道什么 | 在业务项目中打开 |
| --- | --- |
| 初始化检查通过了吗？卡在哪里，下一步做什么？ | `docs/tracking/STATUS.md` |
| 哪些任务已经验收？ | `docs/tracking/TODO.md`。 `[ ]` 表示待办，`[~]` 表示候选待验，`[x]` 表示已验收。 |
| 产品应该怎样工作？结果怎样才算对？ | `docs/tracking/SPEC.md`。涉及计算时再看 `FORMULA.md` 的定义和手算样例。 |
| 用户上次拍板了什么？ | 多对话项目看 `docs/tracking/DECISIONS.md`，按决定编号查受影响的任务。 |

初始化检查报错时，让 AI 按 STATUS 中的具体原因处理并重跑。交接时，AI 会分别说明哪些改动还需在本地存档（commit）、哪些提交还需推送到已有远端（push），按已有授权执行。[共享决定与 Git 交接](./skills/project-guardian/references/06-shared-decisions.md)

也可以把仓库下载到电脑，双击 `使用指南.html`，按场景生成可复制的口令。[离线交互指南](./使用指南.html)

## 一、用「装修房子」秒懂这套机制怎么运作

把你的每一个项目想象成**一套正在装修的房子**，AI 是**施工队长**：

1. **墙上的《最高施工宪章》（项目根目录 `AGENTS.md`）**
   - 记录这个项目的协作约定，你不用记任何命令。里面规定了施工队长的铁律：遇到技术分叉必须打生活化比方让你选、不准私自加戏、不准乱搭平行违建、不准乱复制数据库。
2. **桌上的《追踪文档活页夹》（`docs/tracking/` 目录）**
   - 所有文档用固定名字（不带日期，不产生多份乱麻副本），各司其职：
     - `STATUS.md`（**100 行以内的交接白板**）：写清刚干完哪一步、下一步干什么。哪怕中途断网或新开聊天窗口，你只要说一句 **“按追踪文档继续”**，AI 会核对当前工作区、待办和相关决定后继续！
     - `SPEC.md`（**竣工蓝图说明书**）：只写系统现在长什么样、标准术语叫什么，绝不掺杂修 Bug 流水账。
     - `FORMULA.md`（**算账与算法铁契**，有计算的项目必开）：把公式、分子分母范围、保留几位小数、总和守恒等式和 3 组手算标准答案锁死，AI 没经你批准一个符号都不准改。
     - `TODO.md`（**今日施工微任务单**）：拆成 2–5 分钟能干完的小步子，区分 `[ ] 待办`、`[~] 草稿待验`、`[x] 正式入口实测通过`（防假勾选）。
     - `BACKLOG.md`（**以后再说的想法池 + 历史施工台账**）：把暂时不做的点子收好不干扰主线，把修过的旧问题归档到这里。
3. **工地门口的《红外自动安检闸机》（`verify_guardrails.py` + Git 自动拦截锁）**
   - AI 每次改完代码想存档交工时，门口闸机会自动扫描：
     - 临时搭的实验脚手架分支（`exp/*`）拆干净回主线 `main` 了吗？
     - 有没有偷偷多生出未登记的 `.db / .duckdb / .sqlite` 数据库或超大副本？
     - 改了代码，有没有同步更新 `STATUS.md` 进度白板？
     - `STATUS.md` 有没有写超 100 行变成裹脚布？
   - 检查发现错误时会拦住提交并说明原因。公式和默认入口的验收方法见[验收手册](./skills/project-guardian/references/05-acceptance.md)。

## 二、目录结构一览

```text
Agent-Workflow-Kit/
├── README.md                              # 本使用说明
├── global-rules/
│   └── COLLABORATION_PRINCIPLES.md        # 13 条全局通用《Agent 协作与比喻沟通原则》
├── project-template/                      # 可随时手动复制到任意新项目的空白模板包
│   ├── AGENTS.md                          # 通用项目宪章母版（仅需填底部 10 行配置卡）
│   └── docs/tracking/                     # 标准追踪文档空白模板套组
│       ├── SPEC.md
│       ├── STATUS.md
│       ├── TODO.md
│       ├── BACKLOG.md
│       ├── FORMULA.md
│       └── DECISIONS.md
├── skills/
│   └── project-guardian/                  # 全局主控 Skill（可安装到 Antigravity 与 Codex）
│       ├── SKILL.md                       # 阶段路由入口
│       ├── references/                    # 按阶段读取的工作手册（平时占 0 上下文）
│       └── scripts/
│           ├── init_project.py            # 一键给任意项目装好模板 + 自动安检闸机
│           └── verify_guardrails.py       # 自动安检闸机核心检查脚本
└── scripts/
    └── sync_global.py                     # 修改母版后一键同步刷新 Antigravity 与 Codex 全局目录
```

## 同步母版到两端

若要在两端安装同一套技能和全局协作规则，在下载的 **Agent-Workflow-Kit 仓库根目录**运行：

```sh
python3 scripts/sync_global.py
```

脚本会替换两端已安装的 `project-guardian` 目录，并把母版规则写入 Codex 的 `~/.codex/AGENTS.md` 和 Antigravity 的 `~/.gemini/config/rules/AGENTS.md`。如果你有自定义规则，先备份并核对差异。更新后的规则适用于后续工作。已有业务项目中的需求、决策和验收记录仍在各自项目目录。[同步脚本](./scripts/sync_global.py)
