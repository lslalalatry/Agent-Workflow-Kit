# Agent-Workflow-Kit · 通用 AI 项目治理与追踪文档工具箱

**Agent-Workflow-Kit 帮你和 AI 一起做需要多次修改、多人或多个对话接手的项目。** 你在 Codex 或 Antigravity 里提出需求，核心技能 `project-guardian` 引导 AI 在项目文件里记清你批准了什么、还有什么要做，以及怎样证明做对了。第二天打开项目，接手的人也能找到这些答案。

比如，你让 AI 修改销售报表。「均价已改」可能指公式函数算对了，也可能指你每天打开的首页已经显示了正确结果。两者之间还隔着数据来源、页面接入和实际验收。这个工具箱让你在开工时就说清要验哪个入口，收工时能查到当时用哪批数据、实际看到了什么。

## 这个项目能做什么

| 做项目时遇到的问题 | 你怎么用它 | 你能看到的结果 |
| --- | --- | --- |
| **只有一个想法，担心花时间重做现成功能** | 告诉 AI 谁会用、想解决哪件事。它先查项目已有能力，再看 GitHub 上同领域星数较高、近期确实发布过相关功能或修复的项目，读具体做法，带着取舍逐题和你讨论。 | 产品说明里写明哪些能力沿用、哪些值得借鉴、哪些要自己做，以及用户最后怎样验收。 |
| **需求看似明确，写到一半才发现理解不同** | 需求定稿前，把你的原话和规格放在一起审查。一轮专查逻辑、公式和状态冲突，另一轮专查遗漏、额外功能和难以验证的承诺。支持独立子任务时，可由两位审查者分别检查。 | 会影响业务结果的问题回到你面前拍板。例如，退款订单究竟要从销量、销售额，还是两者中同时扣除。 |
| **同叫“均价”，两个页面却算出不同数字** | 在公式文档写明纳入哪些记录、何时舍入，并把正常、边界、易错三类手算样例接入项目实际使用的计算函数。 | 改错公式时，能看到具体哪组输入失败、预期值多少、实际值多少。 |
| **测试通过，日常打开的页面还是旧结果** | 把日常使用的页面、命令或交付文件登记为默认入口，同时写明数据批次和预期结果。AI 从该入口实测，保存证据。 | 可以分别看到“候选版本已做出”和“用户入口已验收”。勾选完成时，提交检查会核对相应证据和受测版本。 |
| **两个对话同时工作，旧对话把新决定改回去** | 哪个对话收到拍板，哪个对话就在本轮更新决策记录及受影响的待办、规格和公式。另一个对话写回前先核对自己读取的版本。 | 同一工作目录里，尚未提交的新决定也能被读到。通过配套工具写回旧草稿时，会提示重新读取并合并。 |
| **老项目接手后，多出一套页面、一个测试库，没人知道哪个在用** | 让 AI 先盘点现有入口、正式数据路径和未提交改动，把核实过的配置写入项目。初始化脚本运行检查并记录结果。 | 检查会指出未登记的数据库。改了实现却漏更进度时，提交会被拦下。交接时能分清本地还有哪些改动，以及哪些提交还需推送。 |

**什么时候用？** 现有网站改版、长期维护的数据报表、需要跨天推进的自动化工具，都适合采用这套流程。比如给旧网站加导出按钮，可以把“从现有页面按日期筛选后，下载文件中的行与屏幕一致”写作验收条件。一次性的问答或明确的小改动，可以直接处理。

## 销售报表怎样才算改好了

假设团队每天从首页看成交均价。旧首页把两个商品的单价直接平均，10 元和 20 元算出 **15 元**。你想让它反映「顾客实际买走的每一件商品，平均花了多少钱」。

1. **你决定怎么算。** 你确认按成交件数加权。AI 把规则写进产品说明，并用这笔交易核对公式。1 件卖 10 元，9 件卖 20 元，销售额共 190 元，售出 10 件，预期均价为 **19 元**。这时决定已经批准，实现仍在待办。
2. **你在另一个对话补充退款规则。** 你确认全额退款的成交要排除。收到决定的对话把规则、公式和待办一起更新。如果那 9 件全部退款，销售额和件数要同时扣除，预期变为 **10 元**。先前打开的对话下一次写回时，必须保住这条新决定。
3. **AI 改代码，你核对交付。** 假设计算函数已经返回 19 元，日常首页却仍显示 15 元。任务此时保留「候选待验」。AI 查首页实际使用的数据和公式，修正后再打开同一首页，核对未退款时是否显示 19 元、发生上述退款时是否显示 10 元。
4. **下一次对话接手。** 接手的人可以沿着任务编号找到生效决定、手算样例和入口实测记录。如果上轮停在第 2 步，就从待办中的实现任务开始。如果第 3 步已验收，就能查到当时验证的是哪个版本。

每个项目的首页和数据都不同。第一次验收业务结果时，AI 要登记真实入口和预期值，并接入能读到实际输出的检查程序。初始化成功说明项目结构、分支、存储和追踪文档通过了相应检查。缺少数据或账号权限时，业务验收会保持待验，并写明原因。[默认入口与公式验收手册](./skills/project-guardian/references/05-acceptance.md)

仓库里有两个可运行的测试，分别重现“预览已更新、默认入口仍读旧批次”和“两份对话草稿同时改同一条规则”。[验收回归测试](./tests/test_acceptance.py) · [多对话回归测试](./tests/test_chat_sync.py)

## 快速上手

**已经装好技能？直接在 Codex 或 Antigravity 打开你要做的项目文件夹，从下面选一句发给 AI。** 每个业务项目各自初始化一次。第一次了解这个工具，可以先看[它能解决的问题](#这个项目能做什么)。

### 第一次在新电脑安装

准备好 Git 和 Python 3.9 或更高版本。可以把这句话发给 AI，由它完成安装：

> 从 https://github.com/lslalalatry/Agent-Workflow-Kit 下载工具箱。把仓库里的 `skills/project-guardian` 安装到我当前使用的工具中，保留我已有的全局协作规则。安装后告诉我技能的位置，并检查能否运行初始化脚本。

仓库配套的 Codex 技能目录是 `~/.codex/skills/`，Antigravity 技能目录是 `~/.gemini/config/skills/`。如果你想在两端都采用母版的全局规则，见下方「同步母版到两端」。安装完成后，在业务项目里打开新对话。

### 按场景复制一句话

**开新项目**　打开用于新项目的空文件夹，把方括号换成你的想法。

> 调用 `project-guardian` 初始化当前项目。我想做【用一句话描述想法】。先看已有项目里有什么可借鉴，再一次问我一个关键问题，和我确定需求及验收方式。

涉及金额、统计或评分时，补一句 **“开启公式文档，用正常值、边界值和一个易算错的例子核对公式。”** 准备用多个对话协作时，补一句 **“开启决策记录。”**

**接入已有项目**　打开原仓库的根目录。

> 调用 `project-guardian` 接入这个已有项目。先盘点日常使用的入口、数据库和未提交改动，保留业务代码与数据。补齐追踪文档并运行初始化检查，告诉我真实结果和待确认事项。

**日常改功能或修问题**　直接说明要改哪里、做完应该看到什么。例如：

> 默认报表里的均价要按成交件数加权。10 元的商品卖了 1 件，20 元的商品卖了 9 件，结果应为 19 元。把决定同步到相关文档，再从默认报表验收这个例子。

**换对话或第二天接着做**　打开同一项目文件夹。

> 重读当前工作区的决策、TODO、STATUS 和这项任务涉及的产品说明或公式，核对其他对话尚未提交的改动，从上次断点继续。

### 去哪里看结果

| 你想知道什么 | 在业务项目中打开 |
| --- | --- |
| 初始化检查通过了吗？卡在哪里，下一步做什么？ | `docs/tracking/STATUS.md` |
| 哪些任务已经验收？ | `docs/tracking/TODO.md`。 `[ ]` 表示待办，`[~]` 表示候选待验，`[x]` 表示已验收。 |
| 产品应该怎样工作？结果怎样才算对？ | `docs/tracking/SPEC.md`。涉及计算时再看 `FORMULA.md` 的定义和手算样例。 |
| 用户上次拍板了什么？ | 多对话项目看 `docs/tracking/DECISIONS.md`，按决定编号查受影响的任务。 |

初始化检查报错时，让 AI 按 STATUS 中的具体原因处理并重跑。交接时，AI 会分别说明哪些改动还需在本地存档（commit）、哪些提交还需推送到已有远端（push），按已有授权执行。[共享决定与 Git 交接](./skills/project-guardian/references/06-shared-decisions.md)

也可以把仓库下载到电脑，双击 `使用指南.html`，按场景生成可复制的口令。[离线交互指南](./使用指南.html)

## 提交和上传前怎样审查代码

在已接入的项目里，直接对 AI 说「审查这次准备提交的改动」。AI 会沿着实际调用入口读差异，重点检查重复业务逻辑、无用分支、可以省掉的依赖，以及可能破坏原有行为的改动。比如两个报表都复制了退款算法，AI 应指出下次改退款规则会影响哪些页面，并验证它们是否使用同一计算口径。

发现阻断问题先修复，重新暂存并复审。Git 在提交时核对实读过的版本，推送时逐一核对待上传的提交。已经审过且内容一致的提交可以直接沿用记录。旧项目更新技能后，在原仓库根目录让 AI 重新运行初始化，安装这两个检查。新项目会随初始化一起安装。[代码审查操作手册](./skills/project-guardian/references/07-code-review.md)

## 项目里谁负责什么

- **你** 决定业务上怎样才算正确，例如是否排除退款、必须在哪个页面看到结果，以及本次是否授权提交或推送。
- **AI** 读取现有代码和配置、组织需求审查、按已批准的规则实施，并运行项目专用的验收检查。一般协作规则放在项目根目录的 `AGENTS.md`，本项目的具体决定和进度放在 `docs/tracking/`。
- **脚本** 核对能机械判断的事实，例如文档是否齐全、旧草稿是否已经过期、本次提交是否带有相应验收证据。产品是否满足真实需要，取决于用户给出的验收条件和检查程序实际观察的内容。

## 同步母版到两端

若要在两端安装同一套技能和全局协作规则，在下载的 **Agent-Workflow-Kit 仓库根目录**运行：

```sh
python3 scripts/sync_global.py
```

脚本会替换两端已安装的 `project-guardian` 目录，并把母版规则写入 Codex 的 `~/.codex/AGENTS.md` 和 Antigravity 的 `~/.gemini/config/rules/AGENTS.md`。如果你有自定义规则，先备份并核对差异。更新后的规则适用于后续工作。已有业务项目中的需求、决策和验收记录仍在各自项目目录。[同步脚本](./scripts/sync_global.py)
